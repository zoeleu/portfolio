Overview

Given a list of functions and a prompt such as "What is the sum of 2 and 3?", the program doesn't answer 5: it returns the function to call and its typed arguments. A model this small, asked to "answer in JSON", fails often, so the project doesn't rely on it behaving.

It drives the model one token at a time and, at every step, only lets it pick tokens that keep the output valid: a real function name, a real parameter name, and a value of the declared type. The program writes the fixed JSON structure itself; the model makes every choice inside it. String and number values go through a small character-level state machine, which lets the model keep using its natural merged tokens like ", instead of breaking them apart.

Every output is valid JSON by construction. On the sample inputs, all 11 function choices are correct and 10 of 11 calls fully correct. On 302 questions from the Berkeley Function Calling Leaderboard, it made no wrong function choice and no type error, for about 79% strict and 91% lenient accuracy. The 11 samples run in about 25 seconds on an RX 9060 XT.

What it shows

  • How LLMs generate text

    Logits, greedy decoding and masking: one generic loop picks the best allowed token at each step, and skips the model entirely when only one token is possible. _generate_with()

  • Tokenization

    Working with byte-level BPE: decoding every token id once to its real text, and caching which tokens each state allows. _value_table()

  • Prompt engineering

    Qwen's native tool-calling format, and few-shot examples aimed at the errors the benchmark revealed (percentages, units). Prompts live in a validated config, not in code. prompts.json

  • Validation with pydantic

    Function definitions, prompts, results and the prompt config are all pydantic models. models.py

  • Benchmarking and error analysis

    Converting a public benchmark, then reading every failure by hand to separate real mistakes from strict scoring. Performance analysis

  • GPU environments

    ROCm builds of PyTorch for two AMD GPU targets, resolved and locked with uv. pyproject.toml

How AI was used

I used Claude Code as a tool I directed, not as an autonomous builder. I designed the project: the generic constrained loop, the prompt config, when to think and when not to, and the benchmark experiments. I wrote the structure, the data models, the file handling, the first version of the decoder, and a first, crude version of the constrained loop, _generate_with().

Claude then worked only on specific requests from me: refactoring my decoder and _generate_with() into cleaner functions, implementing pieces I specified (including the character state machine, once I'd found that merged tokens broke string closing), setting up ROCm with uv, and analysing benchmark failures, where I chose which fixes to apply. I reviewed everything that stayed in the project and can explain every line. The full breakdown is in the README.
